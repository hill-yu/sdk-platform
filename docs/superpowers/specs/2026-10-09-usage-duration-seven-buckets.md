# 使用时长七桶与每桶总时长规格

## 目标

将 Admin 使用时长汇总从四个重叠/过宽桶细化为七个互斥桶；每桶继续返回设备数和占比，并新增该桶设备最新时长之和（整数秒）。包级汇总保持一包一行，设备明细仍按需加载。

## 固定契约

桶按以下顺序返回，`key` 固定不变：

| key | 范围（秒） |
| --- | --- |
| `le_120` | `<=120` |
| `121_300` | `121–300` |
| `301_600` | `301–600` |
| `601_899` | `601–899` |
| `900_1199` | `900–1199` |
| `1200_1499` | `1200–1499` |
| `ge_1500` | `>=1500` |

每个 bucket 返回：`key`、`count`、`share`、`total_duration_s`。`count` 和 `total_duration_s` 都来自同一条最新设备子查询；`sum(count)=device_count`，`sum(total_duration_s)=package total_duration_s`。有设备时空桶为 `count=0`、`share=0`、`total_duration_s=0`；无设备时沿用现有无行/null 语义。

## 数据口径

在所选北京时间日期/小时范围内，按 `(package_name, device_id)` 使用 `server_ts DESC, id DESC` 选一条最新记录；之后包级聚合，不按 `device_model` 分组。禁止汇总历史记录、前端下载全量设备后重算，禁止从 SQL 返回未聚合的 `model` 列。

## 兼容边界

不改变上传协议 `1–3600` 秒、31 日限制、UTC+8 解释、日志解析、配置接口或数据库 schema。API `buckets` 从四项明确变为七项，前后端必须同版构建。前端保留包总时长、平均时长、最后上报、筛选和按需设备明细；表格不新增 21 列，而是在七个桶单元格中显示“设备数（占比）”与按现有 `formatDuration` 格式显示的总时长秒，并保留内部横向滚动。

## 验收重点

测试覆盖边界 `1/120/121/300/301/600/601/899/900/1199/1200/1499/1500/3600`，多设备、多历史记录、同 timestamp 的 id tie-break、多包、跨机型去重、每桶 count/sum/share、一包一行，以及真实 PostgreSQL SQL 只按聚合结果输出。完成后运行后端全量、前端全量、前端 build、diff check，并记录真实 PostgreSQL 版本；不连接生产。
