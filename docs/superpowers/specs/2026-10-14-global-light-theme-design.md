# SDK 全站明亮风格统一设计

## 用户目标与基线

用户要求所有页面与已经发布的明亮版首页统一，不再按路由切换深浅主题。基线为 master `689a92aef7e4cab611a2b9c98ac62df32cd8d06b`。本设计继承已批准的蓝白风格，不重新定义产品信息架构。

## 视觉规范

- 页面画布 `#f5f7fa`，内容与输入区 `#ffffff`，主要文字 `#1f2937`，次要文字 `#64748b`，边线 `#e5e7eb`。
- 主操作和选中状态 `#2563eb`，选中背景 `#e8f1ff`；成功/警告/错误使用有对比度的深绿、深橙、深红，不能只靠颜色表达状态。
- 统一 6px 控件圆角、14px 基础 UI 字号、明确的 hover/focus/disabled 状态。表格使用浅色表头、深色正文、行分隔线和悬停底色。
- 所有原生 select/option、日期输入、textarea、代码 JSON 区、树编辑器均为浅底深字。移除硬编码的旧深色背景、浅色字体、琥珀主操作与玻璃渐变。
- 保留现有主要布局和信息密度，不把数据表替换成卡片，不引入新的组件库、业务指标或功能入口。

验收执行 `rg -n '#101b1a|#16213e|#f3efe8|#ffb0a8|home-light|rgba\\(255, 255, 255' frontend/src`，每一匹配须移除或在验收记录解释为非生效旧测试/合法例外；不能把图片、测试基线和遮罩误认成暗色主题残留。删除路由浅色条件后，四个路由的测试均断言同一浅色外壳，而非继续保留旧“离开首页变暗”的断言。

## 页面覆盖

1. 公共外壳：四路由始终显示统一白色侧栏、蓝色导航、页头和面包屑；路由标题正确，不再仅首页 light。
2. 数据大盘：延续已发布布局，修复手机端指标、筛选、图表坐标轴裁切；图表保持现有数值和双轴语义。
3. 日志查看：解析统计、原始日志、使用时长三个标签，以及指标配置、任务状态、失败原因抽屉、日志详情、解析详情、资料编辑、导出和包名检索控件全部统一主题。
4. 配置管理：版本列表、10/20/50 分页、配置文件标签、JSON/表格切换、嵌套树增删、保存/发布操作与反馈采用统一主题。
5. 版本管理：列表、表单、按钮和反馈采用统一主题，原请求与操作流程不变。

## 滚动与响应式

- 固定外壳内内容滚动；宽表格在自身容器横向滚动，弹窗/抽屉及配置版本列表内部滚动，分页和主要操作不能被裁切。
- 桌面 1536×1024 与 1366×768、手机 390×844 检查所有路由；小屏筛选自然换行，导航可完整访问，页面本身不能通过 overflow:hidden 掩盖内容超宽。
- 交付需有 DOM overflow 测量；`document.documentElement.scrollWidth <= clientWidth` 只是必要条件，还需检查每个主要控件的边界、内部 scroll 容器及可滚动范围，避免隐藏裁切产生假通过。
- 尊重系统减少动态效果设置，保留键盘焦点；不新增装饰性动画。
- DOM 验收同时记录 documentElement、body、路由根、筛选栏、标签、分页和主按钮的尺寸及 bounding box；逐个滚动表格、抽屉、弹窗和版本列表，验证操作可达。截图覆盖每个页面及 loading/empty/error/disabled/focus/hover 状态，不以首屏一张图代替流程验收。

## 行为边界

- 不改后端、数据库、鉴权、加解密、API 参数/响应、请求超时和任何统计口径。
- 不掺入此前 metrics/overview 慢查询优化。
- 保留筛选与导出条件一致性、按包名查询、日期小时条件、分页、日志复制、配置树增删、未保存编辑内容、保存与发布加载/超时确认行为。
- 不自动推送或部署生产。先实施和本地验收，用户另行授权发布。

## 技术方案

把首页的浅色基础 token 提升为全站默认，去掉 AppLayout 的首页专用主题分支；各功能组件仅补局部语义样式。统一全局变量只能处理基础颜色，必须逐组件清理硬编码深色值，不能依赖全局 `!important` 覆盖所有元素。

TrendChart/StatCard 的默认样式应与全站主题统一，现有可选属性的迁移必须有测试，不保留错误的路由主题切换断言。保持 Vue 3/ECharts 和现有组件边界。

## 实施与验收安排

由既有 gpt-5.6-luna 执行窗口在隔离 worktree 实施，既有独立审查窗口验收，主会话只负责设计与决策。保留主仓所有用户未提交内容。

分为公共主题、日志相关组件、配置及版本管理、回归与视觉四项。先补失败测试，再实施；全量前端测试、构建、diff-check 及 backend 零差异是基础门槛。

使用本地 mock，不读取生产数据，不写入生产。一次批量桌面/移动检查，集中修复，再做一次确认；失败项目明确保留为阻断，不虚称验收通过。

交付包括各页面桌面截图、手机主要流程截图、可访问的本地预览、准确提交 SHA 和逐项验收记录。所有页面同一视觉规范且无主要操作裁切后才作为发布候选。
