# 日志查看与配置树形编辑器设计

## 1. 目标

本次前端增强包含两个功能：

1. 新增独立“日志查看”页面，用于检索、阅读和复制 SDK 上报日志；
2. 将配置管理现有路径表格编辑器替换为支持动态嵌套配置的树形编辑器，并按三个配置文件分别编辑。

配置保存、发布、AES-GCM 加密、PostgreSQL 存储和 SDK 下发协议保持不变。本次不调整日志上报协议和数据库结构。

## 2. 独立日志查看页面

### 2.1 导航和路由

侧边栏新增“日志查看”入口，使用独立页面和路由。页面复用现有 Admin API 鉴权、全局布局、颜色和组件风格。

数据大盘现有事件明细继续保留，用于快速查看 click/log 混合事件；独立日志页面只查询 `event_type=log`。

### 2.2 筛选条件

页面提供以下筛选：

- `package_name`；
- 日志级别：全部、`debug`、`info`、`warn`、`error`；
- `device_id`；
- 开始日期；
- 结束日期。

点击查询时页码重置为第一页。支持刷新、上一页、下一页和空结果提示。默认每页 20 条。

现有事件查询接口已经支持包名、设备、事件类型和日期筛选；日志级别筛选需扩展 Admin 事件查询参数 `log_level`，仅对 `event_type=log` 生效，并基于 `payload->>'level'` 过滤。

### 2.3 日志列表

列表展示：

- 服务端接收时间；
- 日志级别；
- 包名；
- 设备 ID；
- SDK 版本；
- tag；
- message 摘要。

`message` 和 `extra` 不在列表中无限展开，避免超长埋点文本破坏表格布局。日志级别使用易识别的状态标签。

### 2.4 日志详情

点击日志后在页面右侧详情区域展示：

- 时间、包名、设备 ID、SDK 版本；
- level、tag、message；
- 完整 `extra` 原始字符串。

详情支持单独复制 `extra`。复制成功或失败使用现有反馈组件提示。长文本采用等宽字体、自动换行和区域内滚动，不截断实际内容。

### 2.5 错误处理

- 查询失败：保留现有筛选条件，显示明确错误，不清空上一批有效结果；
- Token 无效：沿用 Admin API 的 401 处理；
- 复制失败：显示失败提示，页面内容不变；
- 日志字段为 `null`：界面统一显示 `-`，`extra` 空字符串仍可复制。

## 3. 配置文件标签页

配置详情载入后，将 `config_data` 的三个固定根字段显示为标签页：

- `mainConfig`；
- `newTouchConfig`；
- `newTextRuleConfig`。

新增、删除、复制和排序只影响当前标签页对应的单个配置文件。三个根字段必须始终存在，标签页及根节点不可删除或改名。

选择其他配置版本时，默认切回 `mainConfig`。切换配置文件标签页不会自动保存，也不会丢失当前草稿内存中的修改。

## 4. 树形配置编辑器

### 4.1 节点模型

树节点覆盖标准 JSON 类型：

- object；
- array；
- string；
- number；
- boolean；
- null。

对象子节点保存字段名；数组子节点按实际顺序展示为 `[0]`、`[1]` 等索引，索引由编辑器维护，用户不手工输入。

编辑器内部以真实 JSON 数据为唯一业务状态，树形节点是该数据的可编辑视图；不再通过点号路径作为主要状态，避免字段名包含 `.`、`[` 或 `]` 时无法无损编辑。

### 4.2 对象操作

对象节点支持：

- 展开和折叠；
- 新增子字段；
- 对其子字段新增同级字段；
- 修改字段名；
- 修改节点类型；
- 删除子字段。

同一对象内字段名必须非空且唯一。新增字段默认名称为可编辑占位名，保存和模式切换前必须通过校验。

### 4.3 数组操作

数组节点支持：

- 展开和折叠；
- 新增元素并选择类型；
- 复制元素；
- 删除元素；
- 上移、下移元素。

数组删除或移动后立即重新编号，最终 JSON 不产生稀疏数组。复制采用深拷贝，后续编辑副本不会影响原元素。

### 4.4 类型和值编辑

新增节点和修改类型时可选择六种 JSON 类型。类型切换规则：

- 切换为 string：默认值 `""`；
- 切换为 number：默认值 `0`；
- 切换为 boolean：默认值 `false`；
- 切换为 null：值固定为 `null`；
- 切换为 object：默认值 `{}`；
- 切换为 array：默认值 `[]`。

从非空 object/array 切换为其他类型会删除所有后代，必须二次确认。删除非空 object/array 同样需要确认；删除标量节点不额外确认。

数值输入必须是有限数字。布尔值使用选择控件，不允许自由文本。

### 4.5 只读状态

只有 `draft` 配置可执行树形操作。`published` 和 `archived` 配置仍可展开、折叠、切换标签页和复制内容，但所有增删改、排序和保存操作均禁用。

## 5. 树形与 JSON 双模式

配置编辑器保留两种模式：

- 树形模式：日常新增、删除、复制、排序和修改配置项；
- JSON 模式：批量粘贴、整体检查和高级编辑。

JSON 模式编辑的是完整 `config_data`，仍包含三个根字段；树形模式一次显示当前配置文件标签。

切换规则：

1. JSON → 树形：解析完整 JSON，校验根对象及三个必需根字段，然后载入树；
2. 树形 → JSON：校验所有对象字段名、值类型和结构，然后序列化完整配置；
3. 任一校验失败时阻止切换，保留当前模式和输入，并显示可定位的错误；
4. 往返切换必须保持 JSON 数据语义不变，包括含点号、方括号、空格或中文的合法对象键名。

树形编辑器不承诺保留 JSON 文本的缩进、对象键顺序之外的格式或数字书写形式；保证的是解析后的 JSON 数据无损。

## 6. 保存和发布数据流

保存流程保持现有边界：

1. 前端从当前模式生成完整 `config_data`；
2. 前端执行结构和类型校验；
3. 调用现有配置更新 API；
4. 后端执行三个根字段、大小和业务校验；
5. 后端 AES-GCM 加密后写入 PostgreSQL；
6. 前端按现有 60 秒超时与超时后重查逻辑确认结果。

发布流程、版本分配和三份配置下发逻辑不变。

## 7. 组件边界

前端新增或调整以下职责单一的组件：

- `LogViewer`：日志筛选、分页、列表和选中状态；
- `LogDetail`：单条日志详情和复制；
- `ConfigTreeEditor`：接收单个配置文件 JSON 值并发出不可变更新；
- `ConfigTreeNode`：递归渲染和操作单个节点；
- `ConfigFileTabs`：三个固定配置文件切换。

JSON 数据转换、深拷贝、节点增删改移和校验放在独立工具模块，避免递归组件同时承担业务转换逻辑。

## 8. API 变更

扩展现有接口：

```http
GET /api/admin/events
```

新增可选查询参数：

```text
log_level=debug|info|warn|error
```

约束：

- `log_level` 非法时返回 422；
- `log_level` 仅筛选 `payload.level`；
- 日志页面固定发送 `event_type=log`；
- 响应结构不变，不新增数据库字段。

## 9. 测试与验收

### 9.1 日志页面

1. 导航可进入独立日志页；
2. 默认只查询 log 事件；
3. 包名、级别、设备和日期筛选参数正确；
4. 查询时重置分页；
5. 列表不展开完整 extra；
6. 点击日志展示完整详情；
7. 可复制完整 extra，并有成功/失败反馈；
8. 空结果、字段为空和请求失败状态正确；
9. 后端 `log_level` 校验与 SQL 过滤正确。

### 9.2 树形编辑器

1. 三个配置文件独立切换和编辑；
2. 对象可新增子字段、同级字段、改名和删除；
3. 数组可新增、复制、删除和移动元素；
4. 数组操作后索引连续；
5. 六种 JSON 类型正确编辑和转换；
6. 非空容器删除或类型切换需要确认；
7. 重复或空字段名、非法数字阻止保存和切换；
8. 合法特殊键名可无损编辑；
9. 树形 → JSON → 树形保持数据语义一致；
10. published/archived 只读；
11. 保存仍提交完整三个根配置并进入现有加密流程；
12. 超时重查行为保持有效。

### 9.3 回归

- 后端全量测试通过；
- 前端组件和工具测试通过；
- 前端生产构建通过；
- 本地使用真实 Admin API 完成日志查询、配置读取、树形修改、保存后重读冒烟；
- 不在未明确授权时部署生产。

## 10. 范围限制

- 不修改 SDK 日志上报请求格式；
- 不新增日志删除、导出、实时流式刷新或全文搜索；
- 不修改数据库日志表结构；
- 不修改配置加密、版本号和发布协议；
- 不提供任意数量的配置根文件，仍固定为三个根配置；
- 不对历史已发布配置执行批量结构重写。
