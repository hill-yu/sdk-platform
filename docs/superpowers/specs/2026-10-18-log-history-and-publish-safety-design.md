# 日志检索、历史解析与配置发布确认设计

日期：2026-10-18。代码基线：`6810fbd49ffefc641ca696d3664d263ea6f0fbcb`。

## 已确认需求

1. 解析统计包名改为支持搜索的下拉单选。
2. 解析任务下方增加默认折叠的历史任务列表；选择历史成功任务，在原结果区域展示当次固定结果，后续任务不能覆盖历史内容。
3. 原始日志包名下拉支持搜索；导出包名支持搜索和下拉多选，保留现有导出筛选条件。
4. 查明使用时长重复进入时的加载等待，保留已有筛选与结果，避免标签切换重复查询。
5. 发布前检查未保存修改，存在修改时阻止并提示先保存；读取数据库中的待发布内容，在右侧只读预览，二次确认后发布。预览期间内容变化时重新确认。

用户已明确选择历史结果固定保存，以及未保存时阻止发布。沿用账号登录和明亮主题；主会话制定方案和审查，执行窗口实施，独立窗口验收。

## 现状与证据

- `LogViewer.vue` 的条件渲染会销毁 UsageDurationPanel；该组件 mounted 自动查询近三天全部包名，因此重新切回必定重新查询。
- 生产只读单次计时：默认近三天全部包名 HTTP 200，约 4.1156 秒；测试包名约 0.2142 秒且响应较小。后者不证明大数据包同样快速，也不足以确定具体 SQL 执行瓶颈。
- usage summary 使用 latest-per-device 窗口函数，随后 count 和分页聚合各查询一次。此次不改变累计时长、最新记录和七桶口径；首屏 SQL 性能另列风险，不宣称已经解决。
- 成功解析任务保留带 job_id 的 H1/click stage 行；正式结果表没有 job_id，后续任务按范围覆盖正式行。当前没有历史任务列表和历史结果 API。
- 当前 publishCurrent 校验编辑器 JSON，但实际发布数据库草稿，既没有未保存检测，也没有确认预览。

## 包名选择交互

统一可搜索选择器，分析和原始日志单选，导出多选。分析必须选择一个包名；原始日志保留“全部包名”。输入用于筛选已有包名，提交到接口的值仍为所选完整包名，不把输入片段当查询条件。

打开下拉时加载首批候选；输入 300 毫秒后使用现有 log-packages 搜索能力，有界返回并提供“继续输入缩小范围”提示。处理加载、空结果、失败重试、快速输入时旧响应不覆盖新结果。支持方向键、Enter、Escape 和点击外部关闭。保留 SDK 版本联动：切换原始日志包名清除不适用的 SDK 版本。

导出选择器默认继承已生效的原始日志包名；用户能明确查看所选包名。单包筛选生效时保持该包锁定，避免查询一个包却导出其他包；选择“全部包名”后可批量多选。单包→全部时清空继承包名以及旧多选，要求重新明确选择；全部→单包时清空旧多选并仅使用父级已生效包名，单包A→单包B立即改为B。父级尚未点击查询的草稿条件不改变导出有效条件。SDK 版本、设备、级别、日期、小时和 H1 模式沿用现有契约。

## 历史解析结果

布局顺序：筛选区 → 当前解析任务 → 历史解析结果折叠区 → 原有指标/分布/明细区域。

折叠区首次展开才请求列表；按创建时间、ID 倒序，每页 10 条。按当前生效包名筛选，不受默认近三天条件限制，避免历史任务被默认日期隐藏。显示任务编号、包名、解析时间范围、创建/完成时间、状态及处理数量。失败/取消任务可看状态和错误，不作为成功结果打开。

选择成功任务后，结果区域明确标记“历史任务 #ID”，展示该任务固定的包名、range_start、snapshot_end 和完成时间。查看历史不会启动解析，不修改当前任务或上方待提交筛选；提供“返回当前结果”。创建新任务或应用新查询时退出历史模式。历史请求和当前轮询分开，旧响应不得覆盖新选择。

实现利用成功任务保留的 stage 行作为按 job_id 隔离的只读历史数据源，复用现有指标计算，不重新解析 raw extra。所有历史 overview/configs/targets/failures/H1 以及关联 click 明细都必须使用相同 job_id；禁止退回正式结果表或按日期读取最新结果。数据源模型和job_id为显式查询上下文，贯穿overview每个scalar子查询、attempt_counts/mismatch、target helper及H1→click关联。SQL构造测试逐条断言历史查询引用stage、含正确job_id绑定且不引用正式表，不能仅通过最终数值推断隔离正确。全局别名/公司等展示配置仍使用当前配置，历史事实和数值保持不变。

历史 API 建议：GET `/api/admin/log-analysis/parse-jobs`；GET `/api/admin/log-analysis/parse-jobs/{job_id}/metrics/{overview|configs|targets|failures|h1}`，分别实现明确路由而非任意函数分发。任务范围由服务器读取，不允许客户端覆盖其包名和时间范围。静态 latest 路由排在动态 job_id 前。

旧成功任务仅在保留明细可验证时展示结果。历史可用不变量：status=success；processed_count=total_count且非负；stage H1总行数=job.h1_count（包含failed）；failed行数=job.failed_h1_count；不同(event_id,event_server_ts)数量+no_h1_count=processed_count。每个成功H1的click数量和其decoded_payload.planned_click_attempts数组长度一致，click必须关联到同job同事件复合键/record_index的成功H1，失败H1没有click；不允许孤立click。校验字段缺失、非数组、旧decoder格式无法证明完整时返回不可用，不从声明点击数p推测实际click数量。

合法total=0要求processed/h1/failed/no_h1及stage click全为0；合法非空零H1要求no_h1=processed=total且stage H1/click均空。失败H1保留在H1明细和失败计数中，成功指标聚合维持既有status=success口径。检查在打开具体历史结果时执行，列表不做逐任务重聚合；可返回未验证的可打开候选，进入后明确验证结果。缺失/不完整时返回明确“历史结果不可用”，不能展示最新结果或伪造零值。新任务成功之后不得重新 claim 或更改已完成 stage；失败和取消任务的清理不影响其他任务。本次不增加自动清理或缩短历史保留时间。

## 使用时长重复加载

时长组件首次进入才创建，当前日志页面内切换其他标签时保留实例、筛选、结果和已展开明细。再次进入不自动请求；“查询”提交新条件，“刷新”重新读取已生效条件，并显示最近加载时间。离开整个日志页面后正常释放。

首次仍查询默认近三天全部包名，保留业务行为。加载过程中保留旧结果并明确显示正在更新，失败时不让旧结果伪装成新条件结果。原始七桶、每设备范围内最新上报、总时长与平均时长计算保持原值。首屏 4.1 秒问题作为实测记录，不能把标签缓存描述成数据库查询已经加速。

## 发布确认与一致性

保存/加载成功后记录完整配置和 change_log 的基准。JSON 与树形编辑都比较语义数据，不把缩进/对象键顺序变化误判为内容修改；数组顺序有意义。无效 JSON 或无效树形值直接阻止发布。

流程：点击发布 → 有未保存修改则提示先保存 → 无修改时重新 GET 草稿 → 右侧编辑器显示完整数据库配置且只读 → 明确确认包名、草稿 ID、保存时间 → 确认发布。三份配置文件都可切换预览，默认展示 JSON 内容；不能只预览当前一个文件。取消恢复编辑，不丢失数据。

预览冻结 config_id、updated_at 和内容，确认时提交 expected_updated_at。服务端在包级发布锁内锁定并重新读取草稿行，检查状态和保存时间，不一致返回 409，且不得先上传内容、递增版本或更改状态。草稿保存也锁定行并重新检查 draft，防止保存等待发布锁后覆盖已发布配置。锁顺序统一为发布包锁 → 配置行锁，避免不同草稿发布死锁；保存只取自身行锁。

publish 接口保留旧 API 无请求体调用兼容；新的网页发布必须传 expected_updated_at。精确时间比较使用带时区 datetime，不能截断到秒。409 清除确认状态，重新加载并提示再次预览。发布期间禁止重复确认、切换版本和修改内容。保留原有 60 秒超时及发布状态复核机制，不重复分配版本。

## 验收与边界

- 搜索选择、快速输入竞态、键盘操作、导出全筛选继承及 SDK 版本联动。
- 两次相同范围任务结果不同；打开旧任务仍得到旧 overview、分布、失败和 H1/click 明细。覆盖其他包名、任务缺失、非成功、零 H1 和不完整旧结果。
- 时长标签来回切换不增加 summary 请求；主动刷新增加一次；查询结果保持现有统计口径。
- 未保存的 JSON/树/change_log 均不能发布；语义相同格式变化允许；预览内容来自服务器；取消不发布；409 时无上传/版本变化；保存与发布并发的真实 PostgreSQL 测试。
- 后端相关回归、前端单线程测试、类型检查/build；桌面及 390px 浏览器交互验收。新增功能使用本地合成数据，不写生产业务数据。
- 最终交付精确 SHA、测试证据、操作说明及持续运行的本地服务。合并推送与生产部署不在当前执行授权内。
