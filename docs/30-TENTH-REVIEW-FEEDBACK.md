## 1. 总体评价

审阅人用可控时钟模拟 2,000 个 IP 跨两个清理周期，证明旧 IP 键和过期时间戳均未被回收。我的 3.1 修复每 1000 次清理只删空列表（`if not times`），没过滤 `[0.0]` 这种非空但全部过期的列表。这是典型的"修了一半"的 bug。

---

## 2. 修复记录

### 2.1 [必须修复] 清理器真正过滤过期时间戳 → ✅ 已修复

**根因**：清理条件 `if not times` 只匹配空列表。`[0.0]` 不空，不会被删。

**修复**：遍历所有 IP 键，按当前时间过滤每个键的时间戳。全部过期 → 删键。部分过期 → 保留活跃部分。同时设置最大容量 10000。

**Commit**: `4558e2f`

### 3.2 威胁模型 app_id 描述 → ✅ 已更正
"持有有效 app_id" → "任意字符串作为 app_id，不校验"

**Commit**: `c7268d1`

### 3.3 全部拒绝 HTTP 200 → ✅ 改为 422
`JSONResponse(status_code=422, ...)`

**Commit**: `53a22da` + `8be6529`（测试同步）

### 3.4 click/log 限流桶 → ✅ 共享同一实例
各自独立 `SimpleRateLimiter()` → 统一 `from rate_limit import write_limiter`

**Commit**: `27392b8`
